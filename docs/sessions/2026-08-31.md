it was found the same way the other three were: by running something end to end for the first
time rather than by adding a test to the part that was already covered.

## The bug: every refusal arrived with its reason removed

Running the two-merchant scene over the wire for the first time, the buyer got:

```
net 60: REFUSED -- Error executing tool request_quote
```

No statute, no cap, no suggested alternative. The MSMED refusal — the sentence this project's
entire India-shaped claim rests on, quoted verbatim in the README — was being discarded by the
transport.

The MCP SDK sorts exceptions out of a tool body into two kinds. `ToolError` is *anticipated*
and its message is handed to the caller to read and act on. Anything else is a crash, and the
SDK deliberately withholds the text so an unhandled exception cannot leak internals to a
stranger. That is correct behaviour. Every refusal in `vendable/mcp/server.py` raised
`ValueError`. Eight of them.

**216 tests were green, and none of them was on the far side of the tool dispatcher.** Every
test called `Storefront` directly, where the message is still sitting on the exception object,
fully intact. So the tests were asserting that the *storefront* produces a good refusal, which
it always did, while the buyer received nothing. The wire surface — seven tools, every output
model, every refusal path, the thing an external agent actually consumes — had zero coverage,
in a project whose central claim is that a stranger's agent can transact against it.

`tests/test_mcp_tools.py` now drives `mcp.call_tool`, which runs the same classification the
HTTP transport runs without needing a socket. One of its tests greps the source for
`raise ValueError`, because this failure is silent at runtime and a behavioural test only
catches it on the exact path it happens to cover.

Written up in `what-broke.md`. It is the fourth instance of the same pattern and the entry
says so.

## The console

The first surface in this repo built for the person whose money it is. It answers the two
questions a merchant has when they hand a sales agent the keys — *what is it allowed to do*
and *what has it been doing* — from the same data the buyer transacts against, plus one a log
cannot answer: *what would it say to this buyer?*

Design decision worth recording, because it is the whole page: **approvals render as
hairlines and refusals render as documents.** A refusal gets a full card, a vermillion rule,
and its reason set large in a serif. That is backwards from every dashboard convention, where
success is loud, and it is right here — refusal is the product, and a refusal a merchant has
to decode is a refusal they will learn to ignore.

**Local-only by default.** The page shows cost prices, the margin floor and the discretionary
allowance, which is precisely what SECURITY.md H1/H2 identify as the thing a buyer most wants.
`VENDABLE_CONSOLE=auto` mounts it for `VENDABLE_ENV=local` and nowhere else.

Two things it deliberately does not do: it cannot change policy, and it cannot authorise a
purchase. Those live in `policy.json` and the mandate gate, where they are reviewable and
testable.

## Two more bugs, both from the console

**The console took its own server down on first page load.** It opened an `AuditChain` per
request and closed it in a `finally` — the ordinary shape, and the wrong one here.
`vendable/core/db.py` keeps one connection per file shared by every store, so `close()` closed
the catalog's connection too, and every subsequent request returned 500. The docstring on
`AuditChain.close()` said the opposite of what the code did. Both fixed; `what-broke.md` has
it, and the lesson is that a wrong comment fails silently exactly where tests do not reach —
226 tests use `:memory:`, which `db.connect` never shares, so no test could have observed the
behaviour at all.

**`verify_offline.py` banned loopback, so every async test failed as "network access".** On
Windows `asyncio` builds its event loop's self-pipe from a real TCP socket pair on 127.0.0.1.
The guard now refuses on the *address* rather than on the call: every non-loopback destination
is still refused, and the report line says so instead of claiming "sockets: blocked".
