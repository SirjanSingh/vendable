# 2026-08-30 — Phase 0 and Phase 1

First execution session. The repo did not exist this morning; it now has a deterministic
core, 75 passing tests, and both Phase 0 killer questions answered.

## What shipped

**Phase 0 — bootstrap and spikes.** `D:\projs\vendable`, git on `main`, MIT licence, Python
3.13 venv on D: with `PIP_CACHE_DIR` redirected (C: has 443 MB free and pip would have died
mid-install). Research checkpoint written to `docs/research/PHASE-0.md` with source URLs.

**Phase 1 — the deterministic core.** `money`, `core.models`, `policy.engine`,
`mandate.ap2`, `mandate.gate`, `audit.chain`, and the test suite. No model call in any of it.

## The two questions Phase 0 existed to answer

**Spike A — can a test payment complete headlessly? No.** Payment Links have no pay-by-API
endpoint; the UPI test VPAs belong to Checkout, not to any REST call; S2S JSON v2 is
support-gated per merchant. This invalidated an assumption that had been sitting under the
plan unexamined. Cost: one hour on day one, instead of a rewrite on day four. Resolution in
D-004 — a headless Playwright driver completes the hosted page, the payment stays real, and
the finding goes in the README because the gap between *an agent decided to buy* and *the
money moved* is exactly what agentic payment rails exist to close.

**Spike B — can a stock client connect by URL alone? Yes, proven.** `claude mcp add
--transport http` against a local server returned `✔ Connected` on an unmodified client, and
raw `server/discover`, `tools/list` and `tools/call` all returned 200 with annotations,
`outputSchema` and `structuredContent` intact.

Both were worth running. The research also caught, before any code depended on it, that MCP
spec 2026-07-28 removed the `initialize` handshake and `Mcp-Session-Id`, and that the SDK
renamed `FastMCP` to `MCPServer`. Verified by introspecting the installed package rather than
trusting the write-up — the correct instinct, and it paid.

## The GCP reversal

Mid-session: Cassandra's credits expire 31 Aug, billing detached, project gone. D-002 had
chosen it an hour earlier and was rewritten in place.

Honest assessment of the damage: **smaller than it first looked.** The risk the night-one
deploy existed to retire was never Cloud Run specifically — it was *can a stock client reach
my MCP server by URL and call a tool*, and that is answerable on localhost, which it now has
been. SQLite replaces Firestore with nothing lost, because the audit chain's integrity comes
from the hash chain and not from the store. `.env` replaces Secret Manager.

What genuinely defers: TLS, cold starts, multi-instance behaviour, and the
`TransportSecuritySettings` → `421` hostname trap. All four are pre-empted in code — allowed
hosts already read from an env var — but none is *proven*. This is now the top risk. If
billing does not arrive in time, the submission ships as a run-it-locally repo with a
one-command start, and the README says so plainly.

## Decisions taken

D-001 Python 3.13 everywhere, no local/container split · D-002 local-first, no GCP ·
D-003 caches and venv on D: · D-004 the payment leg needs a browser, and say so ·
D-005 the mandate is a tool argument, not a bearer header · D-006 prove the transport
locally on night one · D-007 `amount == cap` is allowed.

**D-005 is the one worth re-reading.** Claude Desktop's custom-connector dialog cannot send a
custom header — it takes a URL and optional OAuth credentials, nothing else. So the mandate
travels as a `create_purchase` argument. That forces a good property: because the buyer
supplies it, the server may trust *nothing* about it until it has verified signature, expiry,
audience and replay status itself. The transport constraint removed the temptation to
shortcut the gate.

## What the core actually does now

- **Money is integer paise, rates are integer basis points, and every rounding direction is
  chosen and justified.** `discount_bp` rounds up so no floor can be crossed by a rounding
  artefact; `price_at_margin` rounds up so the engine's own counter-offer satisfies the rule
  it was derived from. There is a test asserting exactly that, across a sweep of costs and
  floors.
- **The policy engine returns a counter-offer, not a bare refusal.** A gate that only says no
  makes the LLM guess again; one that says "no, and ₹93.34 is the best I can do" lets it close
  on the first retry.
- **The mandate gate fails closed everywhere.** No `amount_range` means refused, not
  unlimited. `alg=none` is never parsed. Replay is structural — a primary key on
  `(jti, cart_hash)` — because Razorpay has no idempotency header on Orders.
- **The audit chain does not claim immutability.** It claims detectability, and the tests
  prove it against payload edits, deletions, and a self-consistent forgery where the attacker
  recomputes the hash of the row they changed (caught one link later).
