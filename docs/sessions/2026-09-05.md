**Part 2 needs something to carry the weight presence used to carry.** Built:

- `scripts/capture_run.py` — drives the real buyer-agent run against both live servers and
  records the arrival time of every line, not just the text. Output: `vendable/theatre/run.json`
  / `docs/video/assets/run_capture.json`.
- `vendable/theatre/` — a Starlette route (`vendable/theatre/routes`, wired into
  `vendable/mcp/app.py` at `/theatre`, gated local-only same as `/console`) that replays the

  same way and for the same reason as the console.
- `theatre/` — a Vite + React app that is the actual UI for that replay (`sync-run.mjs` pulls
  the capture in at build/dev time). This is new JavaScript tooling in a repo that had
  deliberately avoided any, for `film.html`'s sake. Not relitigated tonight — it exists because
  the replay page needed real interactivity the deterministic-frame approach doesn't buy you,
  and there was no time to write it twice.
- `docs/video/gate-scene.js` replaces the camera pan across the static `architecture.svg` in
  scene 3 of part 1. The pan "explained nothing to anyone who did not already know the system"
  (script.md). The animation shows a buyer handed seven tools, quoted with the volume break
  already applied, pushing for more and being refused, then trying to pay the same cart against
  two different caps — one over, one under — through one shared pixels-per-rupee constant, so
  the cap is something the viewer sees rather than something the film asserts. The static SVG
  still ships for the README and the form; it just isn't in the film anymore.
- `video-remotion/` gained real content: `scripts/make_vo.py`, `make_music_bed.py`,
  `make_intro_sfx.py`, `normalize_vo.py`, and six scene components (`S0Title`..`S6Handoff`).
  This is the "why not Remotion" decision from PRODUCTION.md being revisited under time
  pressure rather than reversed on the record — that doc still says Remotion was declined for
  the frame-by-frame page, and this project sits next to `film.html` rather than replacing it.
  Not fully reconciled tonight; whichever pipeline actually produces the uploaded cut is the
  one that matters, and that should get written down explicitly next session or before upload.
